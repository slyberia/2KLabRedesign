## 1. What this project is

An unofficial redesign of [nba2klab.com](https://www.nba2klab.com), a fan site of NBA 2K testing
data and tools. Author: **Kyle Semple**. Not affiliated with NBA2KLab, 2K, Take-Two or the NBA;
NBA2KLab has not reviewed or approved it.

Goals, in the author's words:

1. Improve the overall UI/UX of the site.
2. Fix the issues found in the original audit: flow, visual hierarchy, and the site's code (`design/audit-2026-09.md`).
3. Improve the appearance and functionality of the tools the site offers.
4. Serve as a portfolio and GitHub entry showing the skills behind Forward Deployed Engineer,
   Front End, Full Stack and Software Engineer roles. The interactivity is part of that evidence.

**Authorship:** AI-assisted design and web development. Kyle directed scope, product and design
decisions, reviewed the output and caught defects. Implementation was generated with AI (Claude)
under that direction and checked with deterministic tests. Describe it this way everywhere; never
as hand-written code, and never in a way that diminishes the direction and review.

## 4. Rebuild brief

**Keep exactly (behavior contracts):** the domain rules (section 5), the reference values
(section 6), the URL and deep-link formats (section 8), the API contract (section 9) and the data.

**Free to change:** visual design, layout, components, copy (within the content rules, section 10).

**Recommended architecture** (recommendation, not a requirement):

- Vite + React + TypeScript. Keep `api/` as Vercel Functions; the front end calls the same endpoints.
- One typed domain module (e.g. `src/domain/`) holding every rule in section 5. In the static build,
  badge, takeover and height logic existed in **three separate copies** (Builder, Builds, Requirements)
  and the attribute-to-category map in about five. They agreed only because tests compared them.
  One module, unit-tested against section 6, removes that.
- Load datasets from `data/` as JSON rather than embedding them in pages. The static
  `builder.html` was 1.16 MB and `reference-table.html` 598 KB almost entirely from embedded data.
- Types for every dataset, generated or hand-written from the actual files.

## 5. Domain rules

### Attributes
21 canonical attributes in 6 categories:
Finishing: Close Shot, Driving Layup, Driving Dunk, Standing Dunk, Post Control ·
Shooting: Mid-Range Shot, Three-Point Shot, Free Throw ·
Playmaking: Pass Accuracy, Ball Handle, Speed With Ball ·
Defense: Interior Defense, Perimeter Defense, Steal, Block ·
Rebounding: Offensive Rebound, Defensive Rebound ·
Physical: Speed, Agility, Strength, Vertical.

Some live pages use other names ("3 Pointer", "Midrange", "Def Reb", "Off Reb", "Speed w/ Ball",
"Passing Accuracy", player ratings' "Layup"). The data in `data/` is already normalized to the canonical names.

### Height gate (badges and animations)
A badge or animation outside its `[minHeight, maxHeight]` is **unreachable at any attribute value**.
Check height first, then attributes. Compare in inches; the range is inclusive. Takeovers and Cap
Breakers have no published height requirements.

### Badge tiers
- A tier threshold of `null` means that tier is **not published as reachable** through that condition.
  Treat it as unreachable, never as 0. Real case: Unpluckable's Post Control path has no HoF value.
- `SINGLE`: the one condition's tier. `OR`: the **best** tier across conditions. `AND`: the **weakest**.
- No badge has more than 2 conditions.

### Animations
Operator by subtype, verified against every row:

| Subtype | Rows | Operator | Basis |
|---|---|---|---|
| jumper | 781 | SINGLE | always exactly 1 threshold |
| dribble | 775 | SINGLE | always exactly 1 of 3 fields |
| shooting | 341 | **OR** | mid == three in every source row, so the data can't distinguish AND from OR. OR is a judgment: which rating governs depends on shot location |
| motionStyle | 353 | AND | agility + speed together |
| finishing | 253 | AND | listed physical attributes together |

**Co-unlock:** for a badge tier at attribute value *v*, list every animation within the height
filter whose threshold on the same attribute is ≤ *v*. AND animations are shown with a note naming
their other required attributes.

### Presets
- 40 Signature Blueprints. **9** publish a full `[floor, ceiling]` for every attribute and a
  `potentialOverall`. The other **31** publish floors only (`ceiling: null`, potential `null`),
  and it's the identical set of 31. Those 31 render **fixed**, like a player card; never invent a
  ceiling. Show an unpublished potential as "—", never "null".
- Blueprints load at their floors. Players (516) are fixed values.
- `bestSkill` has a 7th value, **Balanced** (10 of 40), outside the 6 categories. It uses a neutral color.

### Takeovers (24)
6 `ALWAYS`, 10 `SINGLE`, 6 `AND`, 2 `OR`. No takeover mixes AND and OR. Muscle is a three-condition
AND (Offensive Rebound, Defensive Rebound, Strength ≥ 80).

### Build Specializations (6)
Unlock rule is an OR over AND-groups, parsed from the page structure. Defense is
(Perimeter Defense ≥ 60 AND Steal ≥ 60) OR (Interior Defense ≥ 60 AND Block ≥ 60).
Physicals has no requirement. Each has 10 goals; goal 9 grants 2 category-locked Cap Breakers.

### Cap Breakers (28 total: 26 free + 2 locked)
REP 11 · Crew 4 (levels 16, 22, 29, 40) · Build Specialization 2 (goal 9, locked to category) ·
Lifetime 2 (200 and 400 challenges) · Season 9 (level 40 of each of 9 seasons).
**Derived, never ticked by hand:** REP, Lifetime and Crew come from the user's position on each
roadmap (the sum of Cap Breaker rewards up to that node). Build Specialization is a goal-9 toggle.
Season is a 0 to 9 count.

### Rewards progress
Tracks: REP 39 levels (index 0 to 38) · Lifetime 21 milestones (0 to 20; 300 and 350 are
"Coming Season 2", pending) · Crew 41 levels (0 to 40) · Starter 6 sections / 21 tasks (independent
checklist) · spec9 (boolean) · seasons (0 to 9).

### Builds page sorting
Every metric (attribute rating, badges at tier-or-better, takeovers) is computed at each archetype's
**starting build**, the same values the Builder loads, and the page says so. Ties sort
alphabetically. Badge counts use the Builder's exact rules, including height gating.

## 7. Data

`data/MANIFEST.json` lists every file with its source URL, record count and capture date.
Known gaps and caveats:

- **Time-sensitive:** `2ktv-episode.json` is a snapshot of Episode 4. Season rewards cover Season 1 only.
- **How to Dribble:** 30 move names only. The live guide shows inputs as animated stick diagrams,
  not data. Don't invent inputs.
- **How-To inputs** (`howto-inputs.json`): dunk 4, pass 18, layups 9, post 21 moves, in Xbox notation,
  from 2KLab's page data.
- **Shooting guide:** the live green-window chart is marked placeholder by 2KLab itself. Grade-width

## 8. Routes, tabs and URL formats

Tabs are hash-driven, and pages must also react to `hashchange`: same-page links (footer, account
menu) change only the hash.

| Page | Hashes | Query parameters |
|---|---|---|
| Requirements | `#badges` `#animations` `#takeovers` | `badge`, `tier`, `height=6-2`, `q` (substring search), `attr` (exact attribute), `takeover` |
| Builder | `#my-builds` | `preset=blueprint:<id>` or `player:<id>`, `a`, `focus=<badgeId>` |
| MyCareer | `#attributes` `#specializations` `#rebirth` `#workout` | `spec` |
| Game Details | `#settings` `#controls` `#guides` `#vc-prices` `#face-creations` `#2ktv` `#rewards` | `track=rep\|lifetime\|cap-breakers\|crew\|season\|starter` |
| Builds | `#blueprints` `#community` | none |

**Build share format** (the same format saved builds store):
`?preset=blueprint:certified-bucket&a=mid95.tpt93.bh92.spd90`

- `a` lists only attributes that differ from the archetype floor, in canonical order, as `<code><value>`
  joined by `.`. Codes (letters only, so they can't be misread): cls lay dnk sdk pst mid tpt ft pas bh swb
  id pd stl blk orb drb spd agl str vrt.
- Values outside the published range are clamped **and the user is told**. Unknown or malformed parts
  are ignored. Players and floor-only blueprints ignore `a`.
- Keep `:` literal in the URL. Throttle URL rewrites while dragging (~250 ms): Safari limits
  history updates to about 100 per 30 seconds.

**Requirements → Builder link:** it carries the build's height and reached tier, for example
`reference-table.html?badge=LimitlessRange&height=6-2&tier=silver#badges`. Use `attr=` for exact
attribute filtering: a substring search for "Speed" also matches "Speed With Ball" (a bug found and fixed).

## 9. API contract (`api/`, unchanged by the rebuild)

Demo accounts only. The mockup can't reach real 2KLab accounts. A display name (2 to 20
`[A-Za-z0-9 _-]`) signs in with no password, and the same name reaches the same account. The UI must say so.

| Endpoint | Methods | Notes |
|---|---|---|
| `/api/session` | GET, POST `{name, premium}`, DELETE | HMAC-signed HttpOnly cookie; Premium is set only at account creation |
| `/api/progress` | GET, PUT `{progress: {key: {v, at}}}` | whitelisted keys and ranges (section 5); per-key merge, newer `at` wins |
| `/api/builds` | GET, POST `{name, preset, a}`, DELETE `?id` | server re-validates `a` against blueprint ranges; max 25 per account |
| `/api/community` | GET (public), POST `{action: publish\|rate}`, DELETE `?id` | rating: Premium only, 1 to 5, not your own build; max 10 shared per account, 500 total |

- **Storage:** private Vercel Blob, one JSON file per account plus `community/index.json`.
  Every write is read → change → conditional write (`ifMatch` ETag) → retry with jittered backoff,
  up to 10 attempts. Verified locally: 12 simultaneous ratings all recorded.
- **Other rules:** writes require same-origin, bodies are capped at 16 KB, unknown fields are rejected.
- **Environment:** `BLOB_READ_WRITE_TOKEN` (set when a Blob store is connected) and
  `SESSION_SECRET` (32+ characters).

## 10. Design, accessibility and content rules

**Design system:** `design/tokens.*` and `design/TOKENS.md`. Base theme "Broadcast": dark, red accent,
Barlow Condensed + Hanken Grotesk. Decisions to carry over:

- **Tier colors** (vibrant, contrast-checked 6.4:1 to 11.1:1 on the dark surface): bronze
  `oklch(.700 .150 55)`, silver `oklch(.830 .045 240)`, gold `oklch(.830 .190 92)`, HoF `oklch(.700 .200 300)`.
  Tier colors are **only** for badge tiers. Don't reuse them for other rankings (e.g. Rebirth tiers).
- **Operator chips:** OR red, AND amber. They sit inline where "+" or "/" would go
  ("Mid-Range Shot **OR** Three-Point Shot").
- **Skill colors** mark categories. When cards sit inside a colored category group, don't repeat the color on each card.
- **Badge rows:** cards with tier tiles (numbers only) and one tier legend per page.

**Accessibility:**

- No text under 11px. The original site's 9px AND/OR tag was an audit finding.
- Touch targets at least 24px, and 44px for primary controls. Sliders on touch screens: 44px tall with a 28px thumb.
- Visible focus everywhere; roving tabindex with arrow keys for tabs and roadmaps (one tab stop per group).
- Hover-only behavior must sit behind `@media (hover: hover)`. On touch, `:hover` sticks after a
  tap, and it once made the compare tray impossible to close.
- Respect `prefers-reduced-motion`.

**Content and evidence:**

- Don't reproduce 2KLab's written prose. Summarize facts in original words, attribute measurements
  to the specific 2KLab test, and link to the source.
- Label placeholders, snapshots, pending tests and unresolved results as such. Never present them as measured.
- Don't scrape or reproduce **Premium-gated** 2KLab content.
- Separate complete, partial and planned work in any write-up.

## 12. Lessons from the static build (don't repeat these)

- **Same-page hash links need a `hashchange` handler.** Footer and menu links silently did nothing without one.
- **Script order:** page code ran before the shared account code loaded, so sync never started.
  In React, provide account state through context instead.
- **Full redraws on every input** (`innerHTML`) lost keyboard focus and open/closed state, and needed
  manual workarounds. React's diffing handles this; still, test focus after state changes.
- **A persistent side panel must reflow the page, not overlay it.** An overlay covered the picker and broke clicks.
- **Grid children need `min-width: 0`.** A wide table inside forced horizontal overflow on phones.
- **Exact vs. substring matching:** the attribute filter must match exactly (the Speed bug).
- **Shared devices:** the browser copy of progress must not merge into a different account after
  sign-out. This is still open (section 13).
- **Styles placed inside a generated block were stripped by the build.** A guard now fails the
  build if that happens. The equivalent in the rebuild: keep component styles in their own modules.
- **Verify against the live source before trusting earlier content.** Three Game Details tabs had placeholder data.
- **Delivery folders:** files with identical names overwrote each other. Keep build inputs separate from outputs.

## 13. Hardening backlog (before any public deploy)

Priority order:

1. **Shared-device data mixing:** clear or account-tag the local progress copy on sign-out; never
   merge another account's local copy. Add an end-to-end test (A signs in, marks progress, signs out; B signs in; B's account has none of A's progress).
2. **Real Blob integration test:** `get()` not-found behavior, the ETag format for `ifMatch`,
   read-after-write with `useCache: false`, and concurrent ratings. Skip when `BLOB_READ_WRITE_TOKEN` is absent.
3. **Public-deploy positioning:** `X-Robots-Tag: noindex` and a visible "Unofficial redesign concept" label.
4. **Sessions:** enforce a 30-day maximum age server-side from the cookie's `iat`.
5. **Account names:** "Test User" and "test-user" map to the same account. Reject or make the collision explicit.
6. **Writes:** require `application/json` and a matching Origin header, not only when an Origin is present.
7. **Progress saves:** pending keys are cleared before the server confirms. Keep them until the save succeeds, and retry.
8. **Blob errors:** map rate-limited and unavailable errors to 503 with a clear message.
9. **Content Security Policy.**
10. Pin the Node version (`engines`).

**Decisions for the author, not the agent:** rate limiting (Vercel Firewall rule vs. in-function
limits), moderation of community builds.

## 14. Rules for the agent

- **Evidence only.** Every claim in a report cites a test result, command output or file and line.
  Don't state something works unless a test shows it.
- **Tests before and after every change.** Port the section 6 reference values into unit tests
  first, then build to them.
- **Don't deploy, create cloud resources, or push** without the author's explicit approval.
- **Don't edit `data/`** except to add newly verified data, and update `MANIFEST.json` when you do.
- **Ask before** changing any rule in sections 5, 8 or 9.
- **Report format:** what changed (files), the test that proves it, pass/fail, what was skipped and why,
  and what needs the author's decision.
