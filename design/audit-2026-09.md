# NBA2KLab — Front-End Audit

**Target:** https://www.nba2klab.com
**Date:** 2026-09-06
**Scope:** Logged-out public surface. 25 routes crawled; 4 rendered and instrumented (`/`, `/myplayer-builder`, `/badge-requirements`, `/nba2k-player-ratings`).
**Method:** Raw HTML/CSS/JS retrieval + static analysis; headless Chromium (Playwright) at 1440×900 and 390×844; axe-core 4.10.2; real `Tab` keypress traversal; PerformanceObserver for LCP/CLS.

**Stack observed:** Next.js (Pages Router, `buildId 4LVRA2M9Wg8L4olfMEmNV`), Bootstrap 5 + reactstrap, styled-jsx, formatjs/react-intl, Netlify hosting.

**Not covered:** authenticated/Premium routes, checkout, the 12 non-English locales, real-device network conditions, real-user telemetry. Timing figures below are lab measurements on an unthrottled connection and are optimistic.

---

## Verdict

The engineering is not crude. The **design governance** is.

Delivery fundamentals are in good shape — fast, layout-stable, semantically marked up, and near-clean on automated accessibility. What is missing is a design system, an owner for information architecture, and a release gate on the i18n pipeline. The result reads as "assembled by accretion": every page that needed something new got its own CSS namespace, its own breakpoint, and its own colors, all appended to one global stylesheet that now carries 1,415 `!important` declarations.

The instinct that it feels crudely put together is correct. The cause is not sloppy code — it is the absence of shared constraints.

## A redesign is in flight — homepage only

The homepage runs on a component namespace that exists on no other route crawled: `home-hero`, `home-stats`, `home-stat-value`, `home-features`, `home-feature-card`, `home-builds`, `home-build-card`. Every interior page still uses the legacy `.reqs-page` / `.mpb-page` / Bootstrap `col-xl-4` scaffolding. The swap is also partial *within* the homepage — 8 legacy `col-xl-4` blocks remain alongside the new components. This is a redesign mid-migration, not a finished one.

**The new homepage template.** Five-stat counter band, hero with a CTA pair, three-card feature row, six-card position grid:

| Value | Label |
|---|---|
| 2,595 | Animations Tracked |
| 10 | Years of Testing |
| 735 | Ranked Dribble Moves |
| 327 | Graded Motion Styles |
| 53 | Badges |

This is the current generic landing-page template — the shape modern site builders and AI design tools both default to. Read it as a signal, not a fingerprint: the SaaS-landing convention predates today's AI tools, so the stat band alone doesn't prove machine authorship. What it does prove is stylistic discontinuity with the rest of the site, which is the stronger evidence for "mid-redesign."

**The redesign is higher quality than the original build.** The new homepage is the *only* page in the 25-route crawl with zero i18n key leaks and clean heading structure. This matters for prioritization: the structural fixes in this report are not hypothetical — they are already being applied to page one. The work to do is finish the migration inward and hold the new pages to the standard the homepage now sets, rather than letting the two systems coexist indefinitely (which is how the original 4-system CSS mess formed in the first place).

## P0 — Premium routes gate inconsistently, and some leak content client-side

**Note on scope:** this section documents *how the paywall fails*, as a defect to be closed. It does not contain, and I will not produce, any method of bypassing it — circumventing access control on a paid product is out of scope for this audit regardless of how weak the control is. The finding here is written to be handed to the site owner.

Logged-out behavior across 8 premium routes shows two incompatible enforcement patterns:

| Route | HTTP behavior | Content reaching browser (logged out) |
|---|---|---|
| `premium-dribble-rankings` | Redirect → `/login?returnTo=…` | None — clean server-side gate |
| `premium-layup-rankings` | Redirect → `/login?returnTo=…` | None — clean server-side gate |
| `premium-custom-jumpers` | 200, renders shell | **10-row table rendered before gating** |
| `jumpshot-recommender` | 200, renders shell | Partial (3 gate elements) |
| `motion-styles` | 200, renders shell | Partial (1 gate element) |
| `premium-free-throws` | 200, renders shell | Empty table shell |
| `community-stats` | 200, renders shell | Shell only |
| `premium-dribble-pull-ups` | 200, renders shell | Empty table shell |

**Two defects, both reportable:**

1. **Inconsistent enforcement.** Two routes redirect server-side; six return 200 and gate in React after load. This is the "loads, then redirects" behavior you observed — it's real, and it's the client-side-gated group. The gate treatments themselves are also inconsistent: logged-out body lengths range from 1.4 KB to 4.9 KB, with paywall-element counts of 0, 1, and 3 across pages. There is no single premium-gate component; each page reinvents the "you can't see this" state.

2. **Client-side gating can leak paid content.** `premium-custom-jumpers` renders a 10-row data table in the DOM while logged out. If that table holds real premium data rather than a teaser, it is exposed to anyone viewing source or the network tab — the gate is cosmetic. This is the finding to put in front of the owner: **any premium data must be withheld at the server and never serialized into the logged-out response.** The two clean redirect routes already prove the correct pattern exists in the codebase; it simply isn't applied uniformly.

**Fix:** route all premium paths through the same server-side gate the two working routes use (`getServerSideProps` returning a redirect when unauthenticated, before any premium data is fetched or serialized). Standardize on one premium-gate component for the teaser/upgrade state. Never ship premium rows to an unauthenticated client.

## P0 — Shipped defects

### 1. The Roster Tool ships untranslated i18n keys to crawlers and first paint

`/nba2k-player-ratings` server-renders literal message keys:

```html
<title>nba2k-player-ratings-title</title>
<meta name="description" content="nba2k-player-ratings-meta-description">
<h1 class="reqs-page-title">nba2k-player-ratings-on-page-title</h1>
```

After hydration the client replaces the `<h1>` with "NBA 2K26 All Player Ratings." The `<title>` and `<meta description>` are what search engines, social unfurls, and the browser tab receive.

This is a linked destination from the main nav ("Roster Tool") and from the footer. It is the single most visible defect on the site.

### 2. i18n resolves client-side only — the failure is systemic, not one page

Raw keys found in server-rendered HTML on **4 of 25 sampled routes**:

| Route | Keys leaked into rendered markup |
|---|---|
| `/nba2k-player-ratings` | `nba2k-player-ratings-title`, `-meta-description`, `-on-page-title` |
| `/badge-requirements` | `shooting-badges`, `playmaking-badges`, `finishing-badges`, `defense-badges`, `rebounding-badges`, `physical-badges` (all as `<h2>`) |
| `/badge-descriptions` | `badge-coverage-heading-2k27` |
| `/badge-tier-unlocks` | `badge-tools` |

On `/badge-requirements` the six `<h2>` elements are the section headings for the entire page. They resolve correctly in the browser, which is why this has survived — but every one of those H2s is a keyword-bearing heading being handed to crawlers as a slug.

**Root cause:** translation lookup happens after hydration rather than during SSR/SSG, and nothing in the build fails when a key is missing.

**Fix:** resolve messages server-side, and add a build step that greps rendered output for `/^[a-z0-9]+(-[a-z0-9]+){1,8}$/` inside `title`, `h1`–`h3`, and `meta[name=description]`. Fail the build on a match.

### 3. Keyboard focus is invisible across the primary navigation

Traversed the first 28 tab stops on `/badge-requirements` with real `Tab` keypresses:

**24 of 28 focused elements had `outline: none 0px` and `box-shadow: none`.**

Affected: the hamburger button, the logo link, all eight nav dropdown triggers (Premium, Game Details, Guides, Tools, Badges, Shooting, Recommended Builds, NBA 2k26), the language switcher, **Login**, **Sign-Up**, and the breadcrumb link.

The stylesheet contains 34 `outline: none` / `outline: 0` declarations and 76 `:focus-visible` rules — so the intent to restyle focus exists, but the reset outruns the replacement on the header.

WCAG 2.1 SC 2.4.7 (Focus Visible), Level AA — fail. A keyboard user cannot locate themselves anywhere in the site header.

## P1 — UX and information architecture

### 4. Header overflows the viewport at 1440px, clipping Login and Sign-Up

At 1440×900 (the most common desktop width), `document.body.scrollWidth` is 1446 on `/badge-requirements` and `/nba2k-player-ratings` — a 6px horizontal scrollbar on desktop.

Elements measured extending past the right viewport edge on all four pages:

```
DIV.header-user-slot
DIV.d-lg-inline-block ms-1
DIV.auth-cta
A.auth-btn auth-login
A.auth-btn auth-signup
```

The Login and Sign-Up buttons — the conversion path for a subscription product — are visibly clipped at 1440px. Confirmed in the rendered screenshot: "Login" is cut off mid-word at the right edge.

The eight-item nav bar plus "What's on Premium" plus the language flag consume the row before the auth CTAs get their space, and nothing collapses until the `lg` breakpoint.

### 5. The mega-menu has 97 links and 17 ambiguous duplicates

- 97 links in `<header>`, 95 distinct destinations
- **17 labels appear twice**, pointing to different pages, with no year in the label:

`Best Settings` · `Game Controls` · `Speed and Agility Testing` · `Build Specializations` · `Crew Rewards` · `How to Shoot` · `Animation Requirements` · `Takeover Requirements` · `Badge Descriptions` · `Badge Requirements` · `Badge Tests` · `PGs` · `Centers` · `Sharps` · `Wings` · `Locks` · `PFs`

The only disambiguator is which mega-menu column the user happened to open. A user who wants 2K27 badge requirements and lands in the "NBA 2k26" column gets last year's data with no warning on arrival.

**Fix:** a global game-year switch in the header that scopes the entire nav, replacing the parallel 2K26 tree. Failing that, suffix every duplicated label with its year.

### 6. The most decision-critical value on the badge page is set at 9px

On `/badge-requirements`, whether a badge requires **all** listed attributes or **any one** is encoded in `<span class="bt-logic">` at a computed font size of **9px**, positioned as a corner tag inside the attribute cell.

62 elements on that page render at 9px. The whole-page census:

| Computed size | Element count |
|---|---|
| 9px | 62 |
| 10px / 10.4px | 29 |
| 11px | 59 |
| 11.375px | **620** |
| 12px / 12.5px | 87 |

857 text nodes under 13px on a single page. The 11.375px figure is `.btn-sm` and `<option>` text — including the "Looking for 2K26 Badge Requirements?" cross-year link, which is one of the more important navigational decisions on the page.

The AND/OR distinction also carries a redundant background-tint encoding (dark green vs pale green), which is a second colour-only channel for the same information.

### 7. The badge table duplicates rows instead of grouping them

Measured on the Shooting tab:

- 13 `<tbody>` rows
- **9 unique badge names**
- **0 `rowspan` attributes**

Deadeye, Mini Marksman, Post Fade Phenom, and Quick Trigger each occupy two rows. Each duplicate repeats the badge name and all four tier values (Bronze/Silver/Gold/HOF) plus the height range — data that is identical between the rows.

The results counter reads "13 results" while the user counts 9 badges. The underlying badge-to-attribute relation is being rendered raw instead of grouped for reading.

### 8. Touch targets are far below minimum on mobile

At 390×844:

| Page | Interactive elements | Below 44×44 | Below 24×24 |
|---|---|---|---|
| `/nba2k-player-ratings` | 45 | **43** | **28** |
| `/` (home) | 94 | — | 44 below 32px |
| `/badge-requirements` | 83 | — | 39 below 32px |

WCAG 2.2 SC 2.5.8 sets 24×24 as the Level AA floor; Apple HIG and Material both specify 44/48. The roster tool fails the AA floor on 28 of 45 controls.

### 9. Page length and table width on mobile

| Measurement | Value |
|---|---|
| Homepage document height at 390px | **9,752 px** (≈11.5 viewport heights) |
| `/myplayer-builder` at 390px | 4,892 px |
| `/badge-requirements` at 390px | 4,421 px |
| Roster table scroll width | **3,387 px** inside a 370 px container (9.2× overscroll) |

The roster's sticky name column is implemented correctly, but there is no visual affordance (edge fade, scroll shadow, or hint) indicating that 43 columns extend to the right.

### 10. Game-year drift is not signposted

The site is themed for NBA 2K27, but these routes are still on 2K26 content and are reachable without warning:

- `/nba2k-player-ratings` — "NBA 2K26 All Player Ratings"
- `/teams` — "NBA 2K26 Teams"
- `/nba2k-builds` — "NBA 2K26 Best User-Submitted Builds"
- `/badge-tier-unlocks` — "NBA 2K26 Badge Tiers"

For a product whose value proposition is current, tested data, the absence of a visible "2K26 data" badge on these pages is a trust problem, not just a UX one.

### 11. Single-node breadcrumb on the homepage

The homepage renders a breadcrumb bar containing exactly one item — "NBA2KLab" — with no parent and no destination. It occupies a full horizontal band on both desktop and mobile, and `nav.labs-breadcrumb` was measured overflowing the viewport at 390px. It is pure chrome above the fold.

## P2 — CSS architecture

The following is the mechanical explanation for why the site reads as crude. All figures from `/_next/static/css/6a6cd8afd2ef7213.css`.

| Metric | Value | Reading |
|---|---|---|
| Uncompressed size | **522 KB** | one global sheet, every route |
| Transfer (gzip) | 82 KB | |
| Total rules | 5,827 | |
| `!important` declarations | **1,415** across 935 rules | 16% of all rules are override-by-force |
| Page-scoped namespaces | **46** (`.reqs-page`, `.mpb-page`, `.stadium-finder-page`…) | `.reqs-page` alone appears 589× |
| Bootstrap utility overrides | 82 selectors | e.g. `.stadium-finder-page .bg-light { … !important }` |
| Distinct px breakpoints | **29** | |
| Distinct colour values | 344 hex + 409 rgb/rgba ≈ **750** | against 312 declared custom properties |
| `font-size` in px | 485 declarations | vs 367 in rem |
| Media queries | 298 | |
| Ad-hoc `z-index` ceiling | 9999 (ladder: 2000, 3000, 4000, 4001, 5000, 9999) | |

**Breakpoints.** Bootstrap's five (575.98 / 767.98 / 991.98 / 1199.98 / 1399.98) coexist with twelve hand-added values: 380, 399.98, 420, 480, 526, 600, 639.98, 640, 700, 800, 900, 1500. A breakpoint at 526px is not a device class — it is the width at which one specific component broke. This is reactive responsive design, and it is the clearest fingerprint of accretion.

**Tokens exist but are not authoritative.** 312 custom properties are declared, and font stacks resolve cleanly through `var(--font)` and `var(--mono)`. Yet ~750 distinct literal colour values are hardcoded alongside them. The token layer is decorative.

**Four styling systems in one document.** Bootstrap/reactstrap utilities (`col-xl-4`, `d-block`, `img-fluid`, `carousel-item`, `dropdown-menu`), styled-jsx hash classes (`jsx-438a8f6ecbcd28f7`), hand-written BEM-ish globals (`headernav-mega-link`, `home-feature-card`), and inline `style` attributes — 32 on home, **123 on `/badge-requirements`**, 40 on roster. The `!important` count is the direct consequence: four systems competing for the same cascade with no agreed precedence.

**px font sizes.** 485 `font-size` declarations in px will not respond to a user's browser font-size preference. Browser *zoom* still works; the OS/browser default-text-size setting does not. Given the 857 sub-13px text nodes on the badge page, this compounds.

## Remediation, in priority order

**Ship this week**

1. Fix `/nba2k-player-ratings` title, meta description, and H1. One-line data fix, highest visibility.
2. Restore a focus ring. One rule — `:where(a, button, [role="button"], input, select):focus-visible { outline: 2px solid var(--focus); outline-offset: 2px }` — plus deleting the header's `outline: none`. Closes a Level AA failure across every page.
3. Constrain the header. `min-width: 0` + `flex-shrink` on the nav group so `.auth-cta` never clips; raise the collapse breakpoint. Removes the 6px desktop horizontal scroll at the same time.

**Next sprint**

4. Move i18n resolution to SSR and add the missing-key build gate described in P0-2.
5. Raise `.bt-logic` to ≥12px and promote AND/OR to a text-labelled column or an explicit row grouping. Add `rowspan` (or a grouped sub-row) to the badge table and make the results counter match visible badges.
6. Add a "2K26 data" badge to the four drifted routes.
7. Set a mobile touch-target floor of 44×44 on the roster and header controls.
8. Delete the single-node homepage breadcrumb.

**Structural — this is the actual answer to "why does it feel crude"**

9. **Collapse the breakpoint set to five.** Adopt Bootstrap's and delete the twelve ad-hoc values, fixing components rather than adding widths.
10. **Make the token layer authoritative.** Audit the ~750 colour literals into a palette of 20–30 semantic tokens (`--surface`, `--surface-raised`, `--text`, `--text-muted`, `--tier-bronze`…). Ban raw hex in component CSS via stylelint.
11. **Convert font sizes to a rem type scale** (six steps), and set a floor at 12px for any text carrying meaning.
12. **Pick one styling system.** The 1,415 `!important`s are the bill for running four. Given the Next.js base, CSS Modules or a utility framework — not both, and not alongside styled-jsx.
13. **Split the stylesheet by route.** 46 page-scoped namespaces in a global 522 KB bundle means a visitor to the homepage downloads the CSS for the stadium-finder game. Next.js will code-split this automatically once page CSS lives with page components.
14. **Restructure the nav around a game-year switch.** 97 links with 17 ambiguous duplicates is the IA problem underneath the visual one, and it will not be fixed by restyling.
